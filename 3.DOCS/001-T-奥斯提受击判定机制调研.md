# 调研笔记：奥斯提受击判定 —— 怪物"视玩家掉血"机制的根因与修复路线

> 基于 107、110、111 三个版本的反编译源码逐行比对（解包目录为本地临时工作副本，未纳入仓库，现已不存在）。
> 结论：三版本相关代码**完全一致**，修复逻辑单一源码即可覆盖三版本。
> 游戏当前实机版本：v0.111.0（2026-08-13）。

## 1. 奥斯提（Osty）的伤害吸收机制

### 1.1 召唤与 DieForYou

- 奥斯提由 `OstyCmd.Summon` 召唤（`decompiled-111/MegaCrit.Sts2.Core.Commands/OstyCmd.cs`），召唤时自动施加 `DieForYouPower`（同文件第 75 行）。
- `DieForYouPower.ModifyUnblockedDamageTarget`（`MegaCrit.Sts2.Core.Models.Powers/DieForYouPower.cs:15-30`）：
  - 当本次"未格挡伤害"的目标 == 奥斯提的主人（玩家）的 Creature；
  - 且奥斯提存活；
  - 且伤害是力量攻击（`IsPoweredAttack()` = `ValueProp.Move` 且非 `Unpowered`，见 `ValueProps/ValuePropExtensions.cs`）；
  - 则把"未格挡伤害的目标"从玩家改为奥斯提本身 —— **奥斯提的 HP 就是玩家的"持久格挡"**。
- `PlayerCreatures` 只含 `IsPlayer` 的 Creature（`Combat/CombatState.cs:75`），怪物 `TargetingAllOpponents` 不会把奥斯提当作独立攻击目标；**奥斯提被击中只有 DieForYou 吸收这一条路径**。

### 1.2 CreatureCmd.Damage 结算链路（三版本一致，`Commands/CreatureCmd.cs` ~258-312）

对每个被攻击目标（玩家）：

```
blockedDamage    = 玩家.DamageBlockInternal(攻击力)              // 玩家格挡
unblockedDamage  = max(攻击力 - blockedDamage, 0)               // 【转移前】计算的未格挡伤害
unblockedDamageTarget = Hook.ModifyUnblockedDamageTarget(...)   // DieForYou 把目标改为奥斯提
unblockedDamageResult = unblockedDamageTarget.LoseHpInternal(...) // 奥斯提掉血（若未转移则是玩家掉血）
wasFullyBlocked = !Unblockable && (blockedDamage>0 || 玩家.Block>0) && unblockedDamage==0
```

关键点：

1. **`wasFullyBlocked` 在奥斯提转移之前计算**（基于转移前的 `unblockedDamage`），奥斯提吸收不算"完全格挡"。
2. 当发生转移（originalTarget=玩家 ≠ unblockedDamageTarget=奥斯提）时产生**两个** DamageResult：
   - **奥斯提结果**（`unblockedDamageResult`）：`UnblockedDamage` = 奥斯提损失，`OverkillDamage` = 击穿溢出，`WasFullyBlocked` = false（默认值，else 分支未设置）。
   - **玩家结果**（`damageResult`）：`UnblockedDamage` = 溢出打回玩家的部分（奥斯提没死则为 0），`WasFullyBlocked` = `wasFullyBlocked`（转移前语义）。
3. 两个结果都经 `Hook.AfterDamageGiven` 分发给所有 hook 监听者（`Hook.cs:401-410`，直接分发，战斗结束也触发）。

## 2. 两个怪物的"受击判定"机制

### 2.1 化石追踪者 FossilStalker —— SuckPower（吸取）

- `AfterAddedToRoom` 施加 `SuckPower` 3 层（`Models.Monsters/FossilStalker.cs:48`，111 同）。
- `SuckPower.AfterAttack`（`Models.Powers/SuckPower.cs:22-47`，三版本逐字一致）：

```csharp
foreach (List<DamageResult> item in command.Results) {
    var petHits = item.Where(r => r.Receiver.IsPet).ToList();          // 找奥斯提结果
    foreach (petHit in petHits)
        item.RemoveAll(r => r.Receiver == petHit.Receiver.PetOwner?.Creature); // 【移除玩家结果】
    if (item.Any(r => r.UnblockedDamage > 0)) num++;                   // 【只看奥斯提结果】
}
if (num > 0) PowerCmd.Apply<StrengthPower>(Owner, Amount * num, ...);  // 加力量
```

**结论：游戏刻意（或有意的实现取舍）把"奥斯提被击中"计入"玩家掉血"→ 触发加力。这就是 Bug 根因之一。**

### 2.2 盛碗虫（岩石变体）BowlbugRock —— ImbalancedPower（失衡）

- `AfterAddedToRoom` 施加 `ImbalancedPower` 1 层（`Models.Monsters/BowlbugRock.cs:66`，111 同）。
- `ImbalancedPower.AfterDamageGiven`（`Models.Powers/ImbalancedPower.cs:17-31`，三版本逐字一致）：

```csharp
if (dealer == Owner && result.WasFullyBlocked) {
    if (Owner.Monster is BowlbugRock rock) rock.IsOffBalance = true;  // 下回合晕眩
    else CreatureCmd.Stun(Owner);
}
```

- 状态机：`HEADBUTT_MOVE` 后 `POST_HEADBUTT` 分支按 `IsOffBalance` 决定下回合 `DIZZY_MOVE`（晕眩）或继续 `HEADBUTT_MOVE`（`BowlbugRock.cs:69-82`）；`HeadbuttMove` 结束后若 `IsOffBalance` 当场 `Stun()`（同文件 84-94）。
- **Bug 链路**：奥斯提吸收时，玩家结果 `WasFullyBlocked=false`（转移前语义）且奥斯提结果 `WasFullyBlocked=false`（默认）→ 两次分发都不满足 → 盛碗虫不晕眩，继续进攻。

**注意：BowlbugEgg / BowlbugNectar / BowlbugSilk 均无 ImbalancedPower 机制（已逐一核对），只有 Rock 变体有。需用户实机确认是否只观察到此变体。**

## 3. 影响面评估（修正 WasFullyBlocked 会波及的消费方）

全库读取 `WasFullyBlocked` 的位置（111）：

| 位置 | 消费方 | 说明 |
|---|---|---|
| `CreatureCmd.cs:322` | 伤害数字 VFX | 玩家结果本来无伤害数字，无影响 |
| `CreatureCmd.cs:422` | block_hit 音效/特效 | 只对 `unblockedDamageResult`（奥斯提结果）判断，无影响 |
| `HardenedShellPower.cs:57` | 怪物"硬壳" | 只处理自身被攻击（target==Owner），奥斯提吸收只发生在怪物打玩家，无影响 |
| `ImbalancedPower.cs:19` | 盛碗虫失衡 | 目标机制 |
| `EmotionChip.cs:19` | 玩家遗物"情感芯片" | 检查玩家结果 WasFullyBlocked，语义与修复方向一致（奥斯提受伤≠玩家掉血） |

## 4. 候选修复路线

### 路线 A：底层修改 `CreatureCmd.Damage` 的 wasFullyBlocked 语义（放弃）

- 把"奥斯提吸收"计入完全格挡。但 `Hook.AfterDamageGiven` 在 Damage 方法**内部**执行，Harmony Postfix 无法影响它；async 方法无法中间插入；整体替换需复刻约 100 行逻辑且跨版本签名不同（107 无 `CardPlay` / 111 有）。**风险高，放弃。**

### 路线 B：补丁 `Hook.AfterDamageGiven` 分发器（放弃）

- 分发前修正单个 result 的 WasFullyBlocked。但单结果无法区分"被奥斯提吸收"与"0 伤害攻击"（两者玩家结果同为 `UnblockedDamage=0, WasFullyBlocked=false`）。**放弃。**

### 路线 C（推荐）：补丁两个机制 Power 的行为（Prefix 替换，不动数据）

1. **`SuckPower.AfterAttack`**：把"移除主人结果、检查宠物结果"反转为"**移除宠物结果、检查主人结果**"。
   - 奥斯提吸收 → 玩家结果 `UnblockedDamage=0` → 不加力量 ✓
   - 奥斯提被击穿（溢出打玩家）→ 玩家结果 `UnblockedDamage>0` → 加力量 ✓
   - 无奥斯提 → 原逻辑不变 ✓
2. **`ImbalancedPower.AfterDamageGiven`**：在原条件基础上新增——收到**宠物结果**且 `UnblockedDamage > 0` 且 `OverkillDamage == 0`（奥斯提没被击穿）→ 视作完全格挡（触发 IsOffBalance / Stun）。
   - 奥斯提吸收 → 触发晕眩 ✓
   - 奥斯提被击穿 → 宠物结果 `OverkillDamage>0` 不满足 + 玩家结果 `UnblockedDamage>0` 不满足 → 继续进攻 ✓
   - 0 伤害攻击 → 宠物结果 `UnblockedDamage=0` 不满足 ✓
   - 完全格挡 → 玩家结果 WasFullyBlocked=true 原逻辑 ✓

**8 个场景穷举验证（推导）**：完全格挡 / 无格挡无奥斯提 / 奥斯提完全吸收 / 奥斯提被击穿 / 0 伤害 / AOE 多玩家 / 多段攻击 / 奥斯提死亡离场 —— 逻辑全部自洽。

### 路线 C 的优点

- 不修改任何怪物类（FossilStalker/BowlbugRock 零改动）；补丁目标是**通用机制 Power**（SuckPower / ImbalancedPower 是"受击判定"的载体，未来新怪物若复用它们自动生效）。
- 不修改游戏本体，不动 `WasFullyBlocked` 数据 → EmotionChip / HardenedShell / VFX 等所有其他消费方零波及。
- 判定用 `r.Receiver.IsPet`（通用宠物属性）而非硬编码 Osty 类型 → 未来其他宠物同样适用。
- 三版本代码逐字一致 → 单一 DLL 逻辑即可，无需条件编译（仅需确认补丁目标方法在运行时存在，可加反射兜底）。
- 补丁实现可复用用户既有模式：`[HarmonyPatch(...)]` + `Prefix` 内 `ref Task __result` 赋值替换逻辑（OutbreakOnPlayPatch 先例）。
