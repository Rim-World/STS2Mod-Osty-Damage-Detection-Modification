# 总体设计：奥斯提受击判定修改（OstyDamageDetectionMod）

> 依据 `9.SRC/OstyDamageDetectionMod/` 现有源码、`OstyDamageDetectionMod.json` 清单与 `build.ps1` 反向提炼，不引入源码中不存在的设计。
> 版本 1.0；设计时对应游戏版本 107 / 110 / 111。

## 1. 设计目标

游戏《杀戮尖塔 2》中，亡灵契约师的宠物奥斯提（Osty）通过 `DieForYouPower` 替玩家承受未格挡伤害。部分怪物的「受击判定」把「奥斯提受伤」当成「玩家掉血」，导致两种错误表现：

- 化石追踪者（FossilStalker）的 `SuckPower.AfterAttack` 把宠物承受的伤害计为命中，玩家未掉血也照样加力量。
- 盛碗虫·岩石变体（BowlbugRock）的 `ImbalancedPower.AfterDamageGiven` 在奥斯提吸收时收不到「完全格挡」，因而不失衡、不晕眩，下回合继续进攻。

本 mod 的目标是**在不修改任何怪物类、不修改游戏本体程序集的前提下**纠正上述判定，使三件事同时成立：

1. 奥斯提完全吸收攻击（玩家未掉血）→ 化石追踪者不加力量。
2. 奥斯提完全吸收攻击（玩家未掉血）→ 盛碗虫（石）触发失衡并在下回合晕眩。
3. 奥斯提被击穿、玩家真实掉血 → 两个怪物维持原版行为；未召唤奥斯提时行为也与原版完全一致。

## 2. 模块划分与职责

源码按职责分为三层，工程内部关系保持 Godot C# 项目默认结构（`project.godot` + `.csproj` + 源码目录）：

| 模块 | 文件 | 职责 |
|---|---|---|
| 入口层 | `ModEntry.cs` | 实现游戏 mod 初始化回调（`[ModInitializer("ModLoaded")]`）；持有 `Harmony` 实例；反射查找两个目标方法并逐个安装补丁；输出加载与补丁计数日志；整体异常兜底 |
| 补丁层 | `Patches/SuckPowerAfterAttackPatch.cs` | 替换 `SuckPower.AfterAttack`：反转结果筛选方向，宠物的受击结果不再算作玩家掉血 |
| 补丁层 | `Patches/ImbalancedPowerAfterDamageGivenPatch.cs` | 替换 `ImbalancedPower.AfterDamageGiven`：在「完全格挡」判定中新增宠物被吸收的分支 |
| 辅助层 | `Patches/PowerModelExtensions.cs` | `FlashSafely()` 扩展方法：以反射调用 `PowerModel.Flash()`（protected），失败时静默忽略 |

工程级文件：

| 文件 | 用途 |
|---|---|
| `OstyDamageDetectionMod.csproj` | `Godot.NET.Sdk/4.5.1` + `net9.0`；从游戏目录引用 `sts2.dll` 与 `0Harmony.dll`（`Private=false`，不打进产物）；`NoWarn` 屏蔽 `MSB3270` 平台差异警告 |
| `project.godot` | Godot 工程配置，`config/icon` 指向 `res://OstyDamageDetectionMod/mod_image.png` |
| `export_presets.cfg` | 仅导出 `res://OstyDamageDetectionMod/mod_image.png` 进 pck，`binary_format/architecture="msil"` |
| `OstyDamageDetectionMod.json` | mod 清单：id / name / author / description / version 1.0 / `has_pck: true` / `has_dll: true` / `affects_gameplay: true` / 依赖为空 |
| `build.ps1` | 构建编排：`dotnet build` → Godot `--import` → Godot `--export-pack` → 拷贝产物到游戏 mods 目录 |

## 3. 补丁策略

### 3.1 安装方式：手动 Patch + 反射定位，不用 `PatchAll`

`ModEntry.ModLoaded()` 里不使用 Harmony 的 `PatchAll` 特性自动发现，而是：

1. 用 `typeof(SuckPower).GetMethod(nameof(SuckPower.AfterAttack), Public | Instance)` 与 `typeof(ImbalancedPower).GetMethod(nameof(ImbalancedPower.AfterDamageGiven), ...)` 取得目标方法。
2. 取得后调用 `_harmony.Patch(target, prefix: new HarmonyMethod(...))` 安装，并把成功计数 `patched` 加一；输出 `Log.Info` 记录单个补丁已安装。
3. 取不到时只写 `Log.Warn`（形如 `... not found on this game version, patch skipped`），不抛异常、不中断另一个补丁。
4. 结束时输出 `applied {patched}/2 patches`。

这样做的目的是：目标方法在目标版本区间内存在且签名一致，缺失时只降级不崩溃，因此清单里不设 `min_game_version`。

### 3.2 替换方式：Prefix 返回 false + `ref Task __result`

两个目标方法都是 `async` 方法。补丁采用与既有工程相同的模式：`Prefix` 内计算完整逻辑，把结果任务写入 `ref Task __result` 并 `return false`，跳过原方法体。原方法的行为因此被整体替换，而不是叠加。

### 3.3 两个补丁的判定逻辑

**`SuckPower.AfterAttack`**

- 前置守卫：`command.Attacker == instance.Owner`、目标方不是自己一方（`command.TargetSide != instance.Owner.Side`）、`command.DamageProps.IsPoweredAttack()`；任一不满足则直接返回。
- 逐条攻击结果列表处理：`hit.RemoveAll(r => r.Receiver.IsPet)` —— 先剔除宠物（奥斯提）承受的结果；剩余结果中存在 `UnblockedDamage > 0` 时计一次命中。
- 命中数大于 0 时，闪烁自身（`FlashSafely()`）并 `PowerCmd.Apply<StrengthPower>(choiceContext, Owner, Amount * hitCount, ...)`。

对照原版「移除主人结果、只检查宠物结果」的实现，本补丁把方向反过来：宠物吸收不再等于玩家掉血，而宠物被击穿后溢出到玩家的那份结果仍然会被计入。

**`ImbalancedPower.AfterDamageGiven`**

- 判定改为：`result.WasFullyBlocked || (result.Receiver.IsPet && result.UnblockedDamage > 0 && result.OverkillDamage == 0)`。
- 当 `dealer == instance.Owner` 且上述判定成立时：闪烁自身；若 `Owner.Monster` 不是 `BowlbugRock` 则 `await CreatureCmd.Stun(Owner)`，是 `BowlbugRock` 则置 `IsOffBalance = true`（保留原版两种分支）。

即：宠物承受了实打实的伤害且没有被击穿（`OverkillDamage == 0`），视同玩家「完全格挡」；被击穿时条件不成立，维持「继续进攻」。

### 3.4 通用性取舍

- 宠物判定统一使用 `DamageResult.Receiver.IsPet`（通用属性），不硬编码奥斯提类型，因此其他宠物的吸收行为也走同一逻辑。
- 补丁目标选的是通用机制 Power（`SuckPower`、`ImbalancedPower`），未来复用这两个机制的怪物自动获得修正；自行实现新机制的怪物需要另行适配（说明文档已向玩家声明该边界）。

## 4. 数据流

```
怪物攻击（AttackCommand）
  └─ CreatureCmd.Damage 结算每个目标
        ├─ 玩家格挡 / 未格挡伤害计算
        ├─ DieForYouPower.ModifyUnblockedDamageTarget：把未格挡伤害目标从玩家改为奥斯提
        └─ 产生 DamageResult
              ├─ 奥斯提结果：UnblockedDamage = 宠物损失，OverkillDamage = 击穿溢出
              └─ 玩家结果：UnblockedDamage = 溢出打回玩家的部分，WasFullyBlocked = 转移前语义
                    ↓
        Hook.AfterAttack → SuckPower.AfterAttack ──[本 mod 替换]──▶ 剔除宠物结果后按玩家结果计命中 → 加力量
        Hook.AfterDamageGiven → ImbalancedPower.AfterDamageGiven ──[本 mod 替换]──▶ 完全格挡或宠物被吸收 → 失衡/晕眩
```

补丁本身不持有状态，也不改写 `DamageResult` 的数据字段：只读取已有结果并改变两个 Power 的判定分支，因此 `WasFullyBlocked` 的其他消费方（伤害数字 VFX、`block_hit` 音效、`HardenedShellPower`、`EmotionChip` 等）不受影响。

## 5. 异常处理

| 场景 | 处理 |
|---|---|
| 目标方法在当期版本不存在 | 反射返回 `null` → 跳过该补丁并 `Log.Warn`，另一个补丁与之独立 |
| 补丁安装过程抛异常 | `ModLoaded` 整体 `try/catch`，捕获后 `Log.Error`，不向游戏抛出 |
| `PowerModel.Flash()` 反射调用失败 | `FlashSafely()` 内 `try/catch` 静默忽略；仅丢失视觉闪烁，不影响判定 |
| `FlashMethod` 反射结果为空（方法改名/移除） | `FlashMethod?.Invoke` 直接跳过 |

未记录的部分：补丁内部若发生异常（例如 `command.Results` 结构与预期不同）由谁捕获，源码中没有额外处理，游戏侧行为**未记录**。

## 6. 兼容性设计

- **版本兼容**：目标方法在 107 / 110 / 111 三个版本中逐字一致，单一 DLL 覆盖三版本；清单不设 `min_game_version`，改用运行时反射存在性兜底。
- **依赖**：无 mod 依赖（`dependencies: []`），只依赖游戏自带的 `sts2.dll` 与 `0Harmony.dll`。
- **联机一致性**：清单 `affects_gameplay: true`，声明改动影响玩法。
- **存档安全**：不新增存档字段、不修改数值，关闭 mod 即恢复原版行为。
- **资源兼容**：`has_pck: true` 只为承载 mod 列表图标（`res://OstyDamageDetectionMod/mod_image.png`），不含任何游戏逻辑资源。
- **文本**：纯逻辑 mod，不包含本地化文本，对所有游戏语言一致生效。

## 7. 性能设计

补丁只在攻击结算与伤害钩子被触发时才执行；逻辑是对已有结果列表做一次过滤与一次 `Any` 判断，复杂度与命中次数线性相关，没有每帧逻辑、没有额外线程、没有反射热路径（反射只发生在加载与图标闪烁调用处）。

## 8. 构建与发布设计

`build.ps1`（`$ErrorActionPreference = 'Stop'`，任一步失败即中断）：

1. `dotnet build OstyDamageDetectionMod.csproj -c Debug`，产物在 `.godot/mono/temp/bin/Debug/`。
2. `Godot --headless --import --path <工程根>` 生成 `.import` / `.ctex` 元数据。
3. `Godot --headless --export-pack "Windows Desktop" <mods>/OstyDamageDetectionMod/OstyDamageDetectionMod.pck --path <工程根>`。
4. 拷贝 `OstyDamageDetectionMod.dll`、`OstyDamageDetectionMod.pdb`、`OstyDamageDetectionMod.json` 到游戏 `mods\OstyDamageDetectionMod`，pck 已在第 3 步直接输出到该目录。

构建脚本中的游戏目录与 Godot 可执行文件路径为**本机绝对路径**，换机器需修改脚本。
